## 一、淘汰规则

### 淘汰标准：区分度低

**定义**：一道题的正确率在 50% 左右，且高分段测试者与低分段测试者的答对率没有显著差异——说明这道题「人人都在猜」，无法区分能力强弱。

| 指标 | 判断方式 |
|------|----------|
| 正确率 | 全量测试者的平均正确率 ≈ 40%-60% |
| 区分度 | 将测试者按总分排前 27% 和后 27%，两组的该题正确率差距 < 15% |

> 这不是考前定死的指标，而是在已有足够测试数据后（如 50+ 人次），回顾分析得出的淘汰候选。

### 触发方式

**手动触发**。不自动淘汰。由题库管理者（Linda）定期审视 Google Sheets 数据，决定是否启动一轮淘汰。

### 配额规则：1 换 1，同型同级

| 规则 | 说明 |
|------|------|
| 淘汰 N 题 → 新增 N 题 | 题库总数保持 192 |
| 同题型替换 | 淘汰单选→补单选，淘汰多选→补多选，淘汰判断→补判断 |
| 同难度替换 | 淘汰 diff=1 → 新题 diff=1（标定后） |
| 同维度替换 | 淘汰 dim=1 → 新题 dim=1 |

**目的**：保持全库 45/140/7 的难度分布和题型分布不变。

## 二、历史数据兼容

- **题号**：被淘汰的题号**保留在原位不删除**，`questions.json` 中新题使用新题号
- **Google Sheets**：不处理。历史明细表中旧题号的记录原样保留，不做标红或其他标记
- **淘汰题**：在 `questions.json` 中通过标记字段区分（如 `"active": false`），选题算法跳过

### questions.json 标记方案

```json
{
  "id": "S01",
  "dim": 1,
  "type": "single",
  "diff": 2,
  "pts": 1,
  "active": false,
  "q": "旧题干...",
  "opts": [...],
  "ans": 0
}
```

淘汰时将 `active` 设为 `false`，新增题 `active: true`。选题算法只抽取 `active === true` 的题。

## 三、新题上线检查清单

每轮淘汰+新增后，必须验证：

- [ ] 淘汰题全部标 `"active": false`，新题全部 `"active": true`
- [ ] 新题总数 = 淘汰题总数（192 总量不变）
- [ ] 有效题库（active=true）的题型分布未变
- [ ] 有效题库的 dim/diff 分布与标定基准（45/140/7）偏差 < 2%
- [ ] 新题已完成三维标定（C/I/D）并记录
- [ ] 新题已完成专有名词分级检查（L3 清零、L2 替代）
- [ ] 选题算法在有效题库上模拟运行，不报错（36 题完整走通）
- [ ] 备份当前 `questions.json` 后再写入

## 四、扩展题库

### 扩展规则

**按现有各维度题量等比例放大**。不做维度比例的重新设计。

**公式：**

```
新题量 = 目标总量 - 192
每维度新增 = 新题量 ÷ 4
每维度新增中：
  单选 ≈ 新题量 ÷ 4 × 22/48
  多选 ≈ 新题量 ÷ 4 × 12/48
  判断 ≈ 新题量 ÷ 4 × 12/48
  排序 ≈ 新题量 ÷ 4 × 2/48
```

结果四舍五入后微调到整题数。

### 扩展后影响

| 项目 | 是否变化 |
|------|----------|
| TOTAL_Q（每次测试出题数） | ❌ 保持 **36** |
| MIN_PER_DIM | ❌ 保持 **9** |
| 选题算法 | ❌ 不改变（192→N 增加题池深度，不改变逻辑） |
| 每题 diff/pts 结构 | ❌ 不改变 |
| 百分比等级、满分等级、二维矩阵阈值 | ❌ 不改变 |

> 扩展只增加「备选题池」的丰富度——同一个测试者遇到重复题的概率更低，维度覆盖更均匀。

### 扩展时的配额约束

| 约束 | 说明 |
|------|------|
| 每维度等比例 | 4 维度保持均势 25% / 25% / 25% / 25% |
| 题型比例不变 | 22:12:12:2 守恒 |
| 难度分布不变 | 扩展后全库 diff 分布仍趋近 23% / 73% / 4% |
