## 一、得分计算

```javascript
维度得分率 = dimState[d].totalPts / dimState[d].maxPts × 100
总加权分   = Σ(totalPts) / Σ(maxPts) × 100
```

## 二、百分比等级

| 百分比 | 等级 | CSS 类 | 颜色 |
|---|---|---|---|
| ≥ 80% | 优秀 | lv-a | 🟢 绿 |
| 60-79% | 良好 | lv-b | 🔵 蓝 |
| 40-59% | 待提升 | lv-c | 🟡 黄 |
| < 40% | 薄弱 | lv-d | 🔴 红 |

## 三、满分等级（难度维度）

**设计原理**：自适应选题算法在测试者持续答对时推高难度，满分上限 `Σ(maxPts)` 承载了「系统对你能力的判断」这一隐形信号。两个百分比相同的人，满分高的一方经历了更多困难题的考验，实际能力更强。

```javascript
function maxPtsTier(totalMaxPts) {
  if (totalMaxPts >= 75) return { tier: 3, label: '高难度组', desc: '系统持续出困难题，挑战度高' };
  if (totalMaxPts >= 55) return { tier: 2, label: '中难度组', desc: '中等难度为主' };
  return { tier: 1, label: '低难度组', desc: '以简单题为主' };
}
```

| 满分范围 | 难度等级 | 含义 |
|----------|----------|------|
| ≥ 75 | 🔴 高难度组 | 早期表现强劲，系统持续推高难度至困难题 |
| 55–74 | 🟡 中难度组 | 表现中等，系统以中等难度题为主 |
| < 55 | 🟢 低难度组 | 早期表现偏弱，系统降级出简单题 |

> 满分等级与百分比独立计算。满分上限由首次选题时的难度决定，回退修改不改变满分。

## 四、二维评级矩阵

将百分比等级与满分等级交叉，得到最终二维评级。**中难度为锚点**（评级等于百分比等级，不加不减），高难度全线上移一档，低难度全线下移一档，且低难度最高不超过「良好」。

| | 高难度(≥75) | 中难度(55-74) | 低难度(<55) |
|---|---|---|---|
| **≥80%** | 卓越 | 优秀 | 良好（封顶） |
| **60–79%** | 优秀 | 良好 | 待提升 |
| **40–59%** | 待提升+ | 待提升 | 待提升- |
| **<40%** | 薄弱+ | 薄弱 | 薄弱- |

### 使用规则

- 最终等级取二维矩阵中的值
- 「优秀」同时出现在高难度(60-79%)和中难度(≥80%)两个格——语义一致：在困难题上拿60-79%与在中等题上拿≥80%视为同一档能力
- 低难度组有封顶保护：即使百分比 ≥80%，评级最高为「良好」
- 报告标题展示二维评级（如「待提升+」），附满分等级标签（如「🔴 高难度组」）
- CSS 类仍使用基础等级（lv-a/lv-b/lv-c/lv-d），色值不变
- Google Sheets 汇总表新增「满分等级」和「二维评级」列

### 矩阵可行性（2026-05-18 端到端测试验证）

| 格 | 状态 | 原因 |
|----|------|------|
| 8格 | ✅ 正常产生 | 自适应算法自然覆盖 |
| 3格 | ⚠️ 极罕见 | 高/待提升+、中/薄弱、低/良好 |
| 1格 | ❌ 不可能 | 高/薄弱+（得分率<40%时系统不出困难题，满分堆不到75） |

矩阵12格作为完整框架保留，算法自然只填充可行区。这是自洽而非缺陷。

## 五、报告展示规范

参考模板：`demo-report-v2.html`

### 展示要素

- **二维评级**：基础等级 + 后缀（+ / -），如「良好+」
- **总分**：加权百分比（整数）
- **满分等级**：高/中/低难度组标签（如「🔴 高难度组」）
- **四维度柱状条**：各自百分比
- **等级描述**：高/中/低三段（≥75% / 50-74% / <50%）
- **薄弱项提示**：任一维度 < 60% 时出现，含改进建议
- **雷达图**：四维度得分 vs 60 分基准线
