## 一、得分计算

```javascript
维度得分率 = dimState[d].totalPts / dimState[d].maxPts × 100
总加权分   = Σ(totalPts) / Σ(maxPts) × 100
```

|---|---|---|---|

## 三、满分等级（难度维度）

**设计原理**（2026-05-20 修订）：不再用 ΣmaxPts（受题型 pts 差异污染），改为直接看被测在 diff=3 困难题上的表现。diff=3 题目是 C3+I3+D3 三维高标标定的天花板探测题，一个人能不能答对这类题，直接回答了他能力到没到上限。

```javascript
function diff3PerformanceTier(diff3Count, diff3Correct, overallPct) {
  // diff=3 做题数≥4 且 正确率≥67% → 高难度组
  if (diff3Count >= 4 && diff3Count > 0 && (diff3Correct / diff3Count) >= 2/3)
    return { tier: 3, label: '高难度组', desc: '在困难题上表现稳定，挑战能力强' };
  // 得分率≥40% 但未满足高难度条件 → 中难度组
  if (overallPct >= 40)
    return { tier: 2, label: '中难度组', desc: '以中等难度题为主，仍有提升空间' };
  // 得分率<40% → 低难度组
  return { tier: 1, label: '低难度组', desc: '以简单题为主，基础能力有待加强' };
}
```

| 判定条件 | 难度等级 | 含义 |
|----------|----------|------|
| diff=3 做题≥4 且 正确率≥67% | 🔴 高难度组 | 能稳定应对最困难题目，天花板已被探明 |
| 得分率≥40% 但未满足高难度条件 | 🟡 中难度组 | 中等题为舒适区，困难题尚不稳定 |
| 得分率<40% | 🟢 低难度组 | 以简单题为主，基础能力有待加强 |

> **为什么不用 ΣmaxPts？** pts（题型基础分）不一致：S题 diff=3 满分=2，M题 diff=2 满分=3——同样是 diff=2，多选比单选满分高 1.5 分。ΣmaxPts 衡量的不纯粹是「题有多难」，还混入了「抽到了多少道多选」的运气成分。改用 diff=3 表现则完全不受 pts 差异影响。

> **样本量门槛**：要求 diff=3 做题数≥4，防止只做了 1-2 道困难题就误判等级。自适应算法在测试者持续答对时会推高难度，正常表现下 diff=3 的题目数通常在 10+ 题。

## 四、二维评级矩阵

### 矩阵表格

将百分比等级（行）与满分等级（列）交叉，得到最终二维评级。

**规则**：中难度为锚点（评级 = 百分比等级，不加不减），高难度上移一档，低难度下移一档，低难度最高封顶「良好」。

| | 高难度组 (tier=3) | 中难度组 (tier=2) | 低难度组 (tier=1) |
|---|---|---|---|
| **优秀** ≥80% | 🥇 卓越 | 🥈 优秀 | 🥉 良好（封顶） |
| **良好** 60–79% | 🥈 优秀 | 🥉 良好 | ④ 待提升 |
| **待提升** 40–59% | ⑤ 待提升⁺ | ④ 待提升 | ⑥ 待提升⁻ |
| **薄弱** <40% | ⚠️ 薄弱⁺ | ⑦ 薄弱 | ⑧ 薄弱⁻ |

圆圈数字（①-⑧）为逻辑排序参考，见下文。

按综合能力从高到低排列。同标签内的顺序代表细微差异（两者能力等值，但路径不同）。

| 2 | **优秀** | 中难度·优秀 | 中档题接近满分（≥80%），但困难题正确率不足 67%。**扎实但上限可见**——再往上一档就吃力了。 |

| 9 | **待提升⁻** | 低难度·待提升 | 简单题也刚过线（40-59%），中档题大概率崩。**先打基础**。 |
| 10 | **薄弱⁺** | 高难度·薄弱 | ⚠️ 困难题居然对了但总正确率 <40%。极端反常，实际中几乎不出现。 |
| 11 | **薄弱** | 中难度·薄弱 | 中档题大面积崩（<40%），困难题也做不了。 |

---

### 使用规则

- 最终等级取二维矩阵中的值；同标签内区分来源格（见排序表）
- 「优秀」是两个来源格的等值映射：**在困难题上拿 60-79% ≈ 在中等题上拿 ≥80%**，矩阵视为同一档能力
- 低难度组封顶保护：百分比再高，评级不超过「良好」——防止自适应没推上去导致的虚高
- 报告标题展示二维评级；附满分等级标签（如「🔴 高难度组」）
- CSS 类使用基础等级（lv-a/lv-b/lv-c/lv-d），色值不变
- Google Sheets 汇总表含「满分等级」和「二维评级」列

### 矩阵可行性

| 格 | 状态 | 原因 |
|----|------|------|
| 9 格 | ✅ 正常产生 | 自适应算法自然覆盖 |
| 2 格 | ⚠️ 极罕见 | 低·良好（低难度但 ≥80%，逻辑矛盾）、高·薄弱⁺（困难题对但总分 <40%，极端反常） |
| 1 格 | ⚠️ 罕见 | 低·待提升等中间格在大样本中偶尔出现 |

矩阵 12 格作为完整框架保留，算法自然只填充可行区。未填充的不代表规则缺陷。

### 展示要素

- **二维评级**：基础等级 + 后缀（+ / -），如「良好+」

- **满分等级**：高/中/低难度组标签（如「🔴 高难度组」）
- **四维度柱状条**：各自百分比
- **等级描述**：高/中/低三段（≥75% / 50-74% / <50%）
- **薄弱项提示**：任一维度 < 60% 时出现，含改进建议
- **雷达图**：四维度得分 vs 60 分基准线
